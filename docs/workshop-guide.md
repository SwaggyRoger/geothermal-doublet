# 現場怎麼 demo

給講者的操作筆記。整條約 **20 分鐘**，三段：

```
  intro.html  ──►  進 R 現場跑一次  ──►  report.html
   講清楚在算什麼      讓他們看到它在算        給結論
      5 分鐘             8 分鐘              5 分鐘
```

所有指令與時間都實測過。

## 第 2 段 — 進 R，現場跑一次（8 分鐘）

切到視窗 B，敲：

```bash
Rscript run_all.R
```

**接下來 2 分鐘不要停下來等，照這個節奏講。**

### `02_flow.R`（約 8 秒）— 看著殘差收斂

畫面上這一行會**原地更新**：

```
  迭代  1200   最大質量殘差  1.54e-04 m3/day
```

> 「這是迭代法。這個數字是『還有多少水沒對上帳』。
> 它從 5.4 一路掉到 5.6 的負九次方 —— **這就是收斂長的樣子。**
> 掉不下去，後面全部免談。」

### `03_heat.R`（約 9 秒）— 看著溫度自己往下掉

```
  [============............]  50%   t =  20.0 年   生產井 126.65 degC    4.3 s
```

> 「**不要看進度條，看那個溫度。**
> 前十幾年它一動也不動停在 130 —— 冷水還在路上。
> 然後開始鬆動、加速。這一個數字就是整個案子要回答的東西。」

跑完會印出：

```
  能量守恆相對誤差 = 1.240e-13
  熱突破 (-2 degC) = 6590 day = 18.0 yr   [解析解參考 24.3 yr]
```

> 「能量守恆 10 的負 13 次方 —— 機器精度。
> 熱突破 18 年，解析解 24.3 年。**模擬比較早，因為延散把鋒面抹開了。
> 這是物理，不是誤差。**」

### `04_sweep.R`（約 85 秒）— 28 次模擬一行一行掉出來

這是最長的一段，也是最好講的一段。結果會這樣一行一行出現：

```
  [10/28] L =  800 m, Q =  50.0 L/s -> 16.7 yr
  [11/28] L = 1000 m, Q =  50.0 L/s -> 27.5 yr
  [12/28] L = 1200 m, Q =  50.0 L/s -> 41.2 yr
```

> 「每一行是一次完整的獨立模擬。井距從 800 拉到 1200，
> 壽命從 17 年變 41 年 —— **注意它不是線性的，大約是平方。**
> 這就是剛剛那個解析解說的：時間正比於井距平方除以抽注率。」

跑完直接吐出結論：

```
--- 撐滿 30 年所需的最小井距 ---------------------------
   25.0 L/s  ->  768 m
   50.0 L/s  ->  1037 m
   75.0 L/s  ->  1236 m
  100.0 L/s  ->  1401 m
```

> 「**這四行就是這個 repo 的產品。** 不是圖，是四個可以拿去做決策的數字。」

### `05_viz.R`（約 35 秒）— 組報告

> 「最後這一步把結果組成一個 HTML。**一個檔案，沒有任何外部相依，

## 選配：藏在數字裡的 bug（+5 分鐘）

**時間夠、而且台下有寫模擬的人，才做這一段。** 它很有殺傷力，但需要鋪陳。

開場前先跑 `Rscript R/99_demo_prep.R`（2 分鐘），
它會產生 `outputs/report_bug.html`。

### (1) 當眾改壞一行

`R/01_setup.R` 第 84 行：

```r
C_b <- p$phi * p$rho_c_w + (1 - p$phi) * p$rho_c_s      # 岩水混合體
```

改成（假裝手滑，忘記岩石也會蓄熱）：

```r
C_b <- p$phi * p$rho_c_w
```

### (2) 切到 `report_bug.html` — 不要在台上重跑

> **不要現場跑 `Rscript R/03_heat.R`。**
> 拿掉熱遲滯之後 `dt_max` 縮小 5.7 倍、步數變 5.7 倍，那支要跑 **45 秒**。
> 錯誤版報告已經預先做好了，直接切分頁。

和正確版並排。**圖完全一樣漂亮。**

| | R | 熱突破 | 40 年末溫 | 能量守恆誤差 |
|---|---|---|---|---|
| 正確 | 5.71 | **18.0 年** | 110.7 °C | 1.2e-13 |
| 手滑 | 1.00 | **3.2 年** | 89.6 °C | 1.5e-12 |

**指著最後一欄。** 兩邊都還是綠的，而且都在機器精度。

> 「『我有檢查守恆』聽起來是最紮實的驗證。
> 但它對這個 bug 完全無效 —— 程式確實守恆，它只是守著一個錯的物理。」

### (3) 跑那條抓得到的測試

```bash
Rscript -e "library(testthat); source('R/01_setup.R'); source('R/02_flow.R'); source('R/03_heat.R'); GT_PARAMS_FILE <- normalizePath(GT_PARAMS_FILE); test_file('tests/test_04_retardation.R')"
```

紅色**一秒內**出現（前三條是純算術檢查，不用跑模擬）：

```
── Failure: R 的算式本身就對(直接對參數表算一次)
m$R_thermal not equal to `hand`.
[1] 1 - 5.71 == -4.71
```

後面那 27 秒是它實際跑模擬、量出熱鋒面與水鋒面的速度比再對回理論值，
可以一邊等一邊講收尾那句。

### (4) 收尾

> 「這個 bug 不會 crash、不會噴 warning、圖看起來完全正常、
> 連能量守恆都是綠的。
> 你只會在三年後井打下去、水溫掉得比預期快五倍的時候才發現。
> 而那個時候，你已經找不到當初是哪一行寫錯了。」

## issue → branch → PR 的練習題（Section 07）

repo 裡刻意留了幾個真的值得做的改動，適合當課後練習：

| 難度 | 題目 | 提示 |
|---|---|---|
| ★ | 把注入井從上游改到下游，壽命差多少？ | `01_setup.R` 的 `i_inj` / `i_pro` |
| ★ | 區域坡降 0.0002 → 0.002，結論會不會翻盤？ | `params.csv` 一行 |
| ★★ | 熱突破判準從 −2 °C 改成「掉到 120 °C」 | `T_drop_crit`，順便想想哪個才是工程上該用的 |
| ★★ | 設計掃描加上「第三口井」的情境 | `04_sweep.R` |
| ★★★ | 上下蓋層的熱傳導損失（會讓壽命變長） | 在能量方程加一個匯項，記得同步改能量守恆測試 |
| ★★★ | 把一階上風換成 TVD / 通量限制器，比較數值延散 | `test_05_gringarten.R` 的收斂比值應該會變好 |

流程照 handout：開 issue → 指派審查者 → 開 branch → 改 → 跑測試 →
PR → 審過才合併。

**每一題都要求「測試要跟著改，而且要說明為什麼那樣改」** —— 這比改對程式重要。

## 精準 prompt（Section 06）

如果要講「這個 repo 怎麼生出來的」，這是實際用過的第一個 prompt：

```
你是水文數值模擬的協作者。在這個空 repo 建立 geothermal-doublet 專案。

目標:2D 地熱抽注井對的熱突破模擬。先解穩態水頭場(五點差分 + 兩口井 +
上下游定水頭),由 Darcy 取流速,再以顯式上風差分解溫度的移流–延散,
含熱遲滯因子 R = (ρc)_bulk / (φ(ρc)_w)。

限制:核心運算只用 base R,網格運算一律向量化(禁止逐格 for loop);
資料夾與檔案編號照 README 裡的規範。

驗證:先寫 tests/,包含 (1) 顯式法穩定條件 (2) 質量與能量守恆
(3) 數值量到的熱鋒面速度 / 水流速度要等於理論 R 值,誤差 < 5%。
三個 test 全綠才算完成,把測試輸出貼給我看。
```

五個要素：**角色、目標、物理式子寫清楚、限制（含禁止事項）、
驗收條件（含「把證據貼給我看」）**。

最後一句是關鍵。沒有它，AI 會說「我完成了」；有它，AI 得先讓測試變綠。

## 如果台下問

**「這跟 MODFLOW 比呢？」**
MODFLOW 更完整（3D、非穩態、各種 package）。這裡自己寫網格是為了教學：
用了 wrapper，就看不到穩定條件、守恆、數值延散這些真正會咬人的東西。
實務上當然用 MODFLOW / FEFLOW / TOUGH2。

**「熱突破 18 年可信嗎？」**
當作**上限**。蓋層傳導會讓真實壽命更長，但非均質與裂隙會讓它短很多，
而後者的影響通常大得多。誠實清單在 `README.md` 與 `docs/model-notes.md`。

**「為什麼模擬值比解析解早到？」**
Gringarten–Sauty 是銳利鋒面解，模擬有延散（物理的 + 數值的），
鋒面被抹開，所以 −2 °C 這個判準會提早達到。這是物理，不是誤差。
`test_05_gringarten.R` 用網格收斂證明了數值那部分會隨細化消失。

**「這些 HTML 怎麼做的？」**
`R/00_intro.R` 與 `R/05_viz.R`，plotly（場圖動畫）+ highcharter（歷線與設計圖），
最後自己寫 30 行把 js/css 內嵌成單一 HTML（這台機器沒有 pandoc）。
一個檔案，離線可看，可以直接寄。
