## 1. 三分鐘講完這個 repo（Section 03）

打開資料夾，只講三件事：

1. **README 是身分證** — 負責人、output 位置、參考文獻，都壓日期。
2. **R/ 照編號依序執行** — `01 → 02 → 03 → 04 → 05`。每一支存 `.RData`，
   下一支讀它。所以改顏色只要重跑 `05`，不用整條重來。
3. **參數不寫死在程式裡** — 全部在 `params/params.csv`。
   `gt_params(L_doublet = 1200)` 就能就地覆寫，掃描分析與測試都靠這個。

然後說一句：**「所有 repo 長一樣，換計畫不用重新學。」**

## 2. 現場示範:向量化（Section 05）

這是 R 入門最值錢的一頁。把 `R/03_heat.R` 的時間迴圈叫出來：

```r
Temp <- aP * Temp +
        aW * Temp[, iw] + aE * Temp[, ie] +
        aN * Temp[jn, ] + aS * Temp[js, ] + acst
```

一行更新 16000 格。台下如果有人寫過 MATLAB 或 Python，問他們：
**「如果這裡寫成雙層 for loop 逐格計算，會慢幾倍？」**

真實數字：這支程式從 53 秒優化到 8.1 秒，靠的不是換語言，是把
**所有不隨時間改變的係數搬到迴圈外面**。而且結果一個位元都沒變。

## 3. 現場示範:藏在數字裡的 bug（Section 06 的高潮）

**這一段是整個 workshop 最值得花時間的地方。**

打開 `R/01_setup.R`，找到：

```r
C_b <- p$phi * p$rho_c_w + (1 - p$phi) * p$rho_c_s
```

當場把它改成（假裝手滑，忘記岩石也會蓄熱）：

```r
C_b <- p$phi * p$rho_c_w
```

然後：

```bash
Rscript R/03_heat.R
Rscript R/05_viz.R
```

**打開報告 —— 圖完全正常。** 溫度場漂亮、流線漂亮、歷線平滑。
如果台下沒有人記得正確答案，沒有任何人看得出來這張圖是錯的。

實測差距（可以直接把這張表投出來）：

| | R | 熱突破 | 40 年末溫 | 能量守恆誤差 |
|---|---|---|---|---|
| 正確 | 5.71 | **18.0 年** | 110.7 °C | 1.2e-13 |
| 手滑 | 1.00 | **3.2 年** | 89.6 °C | 1.5e-12 |

**注意最後一欄：兩邊的能量守恆都還是綠的。** 這才是重點 ——
「檢查守恆」這種聽起來最紮實的測試，對這個 bug 完全無效。
因為程式確實守恆，它只是守著一個錯的物理。

然後跑：

```bash
Rscript tests/run_tests.R
```

`test_01`（質量）綠、`test_02`（穩定）綠、`test_03`（能量）綠、
**`test_04_retardation.R` 紅**，訊息直接告訴你 R 應該是 5.71。

**要講的重點不是「TDD 很好」，是這句：**
> 「這個 bug 不會 crash、不會噴 warning、圖看起來完全正常。
> 你只會在三年後井打下去、水溫掉得比預期快五倍的時候才發現。
> 而那個時候你已經找不到當初是哪一行寫錯了。」

改回來，重跑，全綠。

### 備用的第二個示範（如果時間夠）

在 `R/03_heat.R` 把 `dt_safety` 從 0.8 改成 2.0（或直接改 `params.csv`），
重跑 `03_heat.R`。溫度會噴到 10¹⁴ °C。`test_02_cfl.R` 抓得到。

## 4. 現場示範:精準 prompt（Section 06）

如果要重現「從空資料夾開始」的過程，這是實際用過的第一個 prompt：

```
你是水文數值模擬的協作者。在這個空 repo 建立 geothermal-doublet 專案。

目標:2D 地熱抽注井對的熱突破模擬。先解穩態水頭場(五點差分 + 兩口井 +
上下游定水頭),由 Darcy 取流速,再以顯式上風差分解溫度的移流–延散,
含熱遲滯因子 R = (ρc)_bulk / (φ(ρc)_w)。

限制:核心運算只用 base R,網格運算一律向量化(禁止逐格 for loop);
資料夾與檔案編號照 README 裡的規範。

驗證:先寫 tests/,包含 (1) 顯式法穩定條件 (2) 質量與能量守恆
(3) 數值量到的熱鋒面速度 / 水流速度要等於理論 R 值,誤差 < 5%。
三個 test 全綠才算完成,把測試輸出貼給我看。
```

值得指出的五個要素：**角色、目標、物理式子寫清楚、限制（含禁止事項）、
驗收條件（含「把證據貼給我看」）**。

最後一句是關鍵。沒有它，AI 會說「我完成了」；有它，AI 得先讓測試變綠。

## 5. issue → branch → PR 的練習題（Section 07）

repo 裡刻意留了幾個真的值得做的改動，適合當現場或課後練習：

| 難度 | 題目 | 提示 |
|---|---|---|
| ★ | 把注入井從上游改到下游，壽命差多少？ | `01_setup.R` 的 `i_inj` / `i_pro` |
| ★ | 區域坡降 0.0002 → 0.002，結論會不會翻盤？ | `params.csv` 一行 |
| ★★ | 熱突破判準從 −2 °C 改成「掉到 120 °C」 | `T_drop_crit`，順便想想哪個才是工程上該用的 |
| ★★ | 設計掃描加上「第三口井」的情境 | `04_sweep.R` |
| ★★★ | 上下蓋層的熱傳導損失（會讓壽命變長） | 在能量方程加一個匯項，記得同步改能量守恆測試 |
| ★★★ | 把一階上風換成 TVD / 通量限制器，比較數值延散 | `test_05_gringarten.R` 的收斂比值應該會變好 |

流程照 handout：開 issue → 指派審查者 → 開 branch → 改 → 跑測試 →
PR → 審過才合併。

**每一題都要求「測試要跟著改，而且要說明為什麼那樣改」** —— 這比改對程式重要。

## 6. 如果台下問

**「這跟 MODFLOW 比呢？」**
MODFLOW 更完整（3D、非穩態、各種 package）。這裡自己寫網格是為了教學：
用了 wrapper，就看不到穩定條件、守恆、數值延散這些真正會咬人的東西。
實務上當然用 MODFLOW / FEFLOW / TOUGH2。

**「熱突破 18 年可信嗎？」**
當作**上限**。蓋層傳導會讓真實壽命更長，但非均質與裂隙會讓它短很多，
而後者的影響通常大得多。誠實清單在 `README.md` 與 `docs/model-notes.md`。

**「為什麼模擬值比解析解早到？」**
Gringarten–Sauty 是銳利鋒面解，模擬有延散（物理的 + 數值的），
鋒面被抹開，所以 −2 °C 這個判準會提早達到。這是物理，不是誤差。
`test_05_gringarten.R` 用網格收斂證明了數值那部分會隨細化消失。

**「這個報告怎麼做的？」**
`R/05_viz.R`，plotly（場圖動畫）+ highcharter（歷線與設計圖），
最後自己寫 30 行把 js/css 內嵌成單一 HTML（這台機器沒有 pandoc）。
一個檔案，離線可看，可以直接寄。
