# 模型筆記 — 假設、簡化與數值決策

記錄「為什麼這樣做」。程式碼記得住「怎麼做」，記不住「當初為什麼不那樣做」。

---

## 1. 控制方程式

### 1.1 流場（穩態）

侷限含水層，導水係數 `Tr = K·b`：

```
Tr · ∇²h = −Q_well / (dx·dy)
```

離散成五點差分後整理成「四鄰平均 + 源匯」的形式，`dx` 會消掉：

```
h_P = ( h_N + h_S + h_W + h_E + Q_well/Tr ) / 4
```

面上的體積流率同樣不含 `dx`：

```
Q_face = Tr · (h_上游 − h_下游)      [m³/day]
```

因為 `Q = −K·(Δh/dx)·(dx·b) = K·b·Δh`。這個化簡讓質量守恆的檢查變得極乾淨，
也是 `gt_flow_imbalance()` 那幾行的來源。

**解法：紅黑 SOR。** 鬆弛因子取矩形域的經典估計 `ω = 2/(1+sin(π/n))`
（本組態 ≈ 1.9615）。收斂到最大格點殘差 / Tr < 1e-11，約 2400 次迭代、10 秒。

為什麼不用 `Matrix` 套件直接解稀疏矩陣？會更快，但學生就看不到「網格法在做
什麼」了。這個 repo 的教學重點就是那個迴圈。

### 1.2 熱傳輸（暫態）

**刻意寫成能量的有限體積式，不是 dT/dt 的偏微分方程。** 對每一格：

```
V · C_bulk · dTemp/dt = Σ(面能量通量) + 井 + 邊界

  平流：C_water · Q_face · Temp_供給格        （一階上風）
  傳導：λ_eff · b · (Temp_鄰 − Temp_P)        （A_face/dx = b，dx 又消掉）
  延散：λ_eff = λ_bulk + C_water · α_L · |Darcy 通量|
```

換來三件事：

1. **能量守恆成為恆等式。** 內部每個面對兩邊的貢獻數值完全相同、符號相反，
   全場加總時兩兩相消。總能量只能被井與邊界改變 → 可測到 1e-13。
2. **井的源匯項自然正確。** 注入帶進 `C_w·Q·T_inj`，生產帶走 `C_w·Q·Temp_本格`。
   不需要額外湊。
3. **熱遲滯 R 是「長出來的」而不是「乘上去的」。** 程式裡沒有任何一行寫
   `* R`。R 只出現在報告與測試裡，當作理論值去對照模擬量到的比值。

### 1.3 熱遲滯因子

```
R = C_bulk / (φ · C_water)
  = (φ·ρc_w + (1−φ)·ρc_s) / (φ·ρc_w)
  = (0.10×4.2e6 + 0.90×2.2e6) / (0.10×4.2e6)
  = 2.4e6 / 0.42e6
  = 5.71
```

把能量方程式除以 `C_bulk`，並令 `v = q/φ`：

```
∂T/∂t = (1/R) · [ −v·∇T + α_L|v|·∇²T ]
```

**平流與延散帶著同一個 1/R。** 所以熱的解就是保守示蹤劑的解在時間軸上拉長
R 倍 —— 這是 `test_04_retardation.R` 能要求 0.5% 精度的原因（實測誤差 0.000%）。

## 2. 初始與邊界條件

| | 設定 | 備註 |
|---|---|---|
| IC（水頭） | 均勻 `h_ref` | 只是 SOR 的起始猜測，不影響穩態解 |
| IC（溫度） | 全場 `T_res = 130 °C` | |
| 左右邊界 | 定水頭（Dirichlet），`h_ref` 與 `h_ref − i·Lx` | 區域水力坡降 |
| 上下邊界 | 不透水（no-flow），鏡像 padding | |
| 邊界溫度 | 流入帶 `T_res`，流出帶本格溫度（上風判斷） | 見下 |
| 邊界傳導 | 零（絕熱） | 只有平流進出 |

**定水頭格的處理方式值得說明。** 它們同時是水的來源/去處。做法是把它們的質量
不平衡量 `Q_ext` 算出來，當成一個「外部面」的通量：

```
Q_ext = Tr·(4·h_P − Σh_鄰) − Q_well
```

在自由格這個值必須是 0（→ 質量守恆測試）；在定水頭格它就是邊界通量
（→ 熱傳輸的邊界條件）。同一個式子做兩件事，而且兩者都可測。

`Q_ext > 0`（流入）帶 `T_res` 進來，`Q_ext < 0`（流出）帶走本格溫度。
若把流出也寫成帶 `T_res`，能量守恆測試會立刻紅 —— 而且是**唯一**會紅的一條。

## 3. 數值決策

### 3.1 穩定條件

更新式攤開後是：

```
Temp_new = (1 + dt·cP/(V·C_bulk)) · Temp + (全部非負的鄰格項) + 常數
```

`cP` 恆為負。條件就是「自己這一格的係數不能變負」：

```
dt ≤ V · C_bulk / (−cP)
```

**這不是查表來的 CFL 公式，是從自己寫的離散式讀出來的。** 好處是換任何參數
（抽注率、網格、延散度）它都自動正確；壞處是要真的理解自己在寫什麼。

實測（`test_02_cfl.R`）：

| dt | 結果 |
|---|---|
| 0.8 × 上限（預設） | 溫度落在 [70, 130]，穩 |
| 1.2 × 上限 | **還是穩的** — 上限是充分條件，取全場最嚴的一格 |
| 2 × 上限 | 溫度噴到 ±10¹⁴ °C |
| 3 × 上限 | ±10³² °C |

1.2 倍還活著這件事才是真正危險的地方：**它不會在你稍微越界時警告你**，
只會在某天有人把抽注率調高之後，突然全錯。

### 3.2 數值延散

一階上風差分的數值延散量級是 `v·dx/2`。物理延散度設為 `α_L = 20 m`，
在 `dx = 20 m` 的網格上兩者同量級。

`test_05_gringarten.R` 直接量了這件事 —— 純平流（關掉 `λ_bulk` 與 `α_L`）時，
示蹤劑 1% 到達時間 / 解析解：

| dx | 比值 |
|---|---|
| 50 m | 0.491 |
| 25 m | 0.637 |
| 12.5 m | 0.752 |

單調從下方逼近 1.0。**這比「誤差 < 2%」那種假精確的判準誠實得多**：
它證明的是「誤差會隨網格細化而消失」，而不是「在這一個網格上剛好對」。

### 3.3 效能

時間迴圈裡的所有係數（平流上風權重、傳導導度、井、邊界）都只和已解好的
流場有關，所以在迴圈開始前一次算完，攤成六個常數矩陣。迴圈本體只剩：

```r
Temp <- aP*Temp + aW*Temp[, iw] + aE*Temp[, ie] +
        aN*Temp[jn, ] + aS*Temp[js, ] + acst
```

40 年、6920 步、16000 格：**53 秒 → 8.1 秒**，結果一個位元都沒變
（生產井末溫 110.72 °C、`dt_max` 相同）。這也讓 28 次模擬的設計掃描
從不可行變成 100 秒。

## 4. 參數的來源與合理性

全部是合成值，但取在真實地熱儲層的合理範圍：

| 參數 | 值 | 說明 |
|---|---|---|
| `K` | 5 m/day | 裂隙型 / 砂岩儲層 |
| `b` | 100 m | |
| `φ` | 0.10 | 有效孔隙率 |
| `ρc_w` | 4.2e6 J/m³/K | 水 |
| `ρc_s` | 2.2e6 J/m³/K | 岩石（≈2600 kg/m³ × 850 J/kg/K） |
| `λ_bulk` | 2.5 W/m/K | 換算成 216000 J/m/day/K |
| `α_L` | 20 m | 場尺度縱向延散度 |
| `Q_well` | 4320 m³/day | = 50 L/s，典型雙井系統 |
| `T_res / T_inj` | 130 / 70 °C | |
| `grad_regional` | 0.0002 | 刻意取小 |

**區域坡降為什麼取這麼小。** 取 0.0002 時區域滲流速度約 0.01 m/day，40 年
只走 146 m，熱鋒面更只有 26 m —— 相對於井對誘導的流速（兩井中點約
0.34 m/day）只佔 3%，所以與 Gringarten–Sauty（假設無區域流）的對照仍然成立。

把它改成 0.002 會讓區域漂移變成一階效應，值得當作課後練習：
**注入井放上游還是下游，壽命差多少？**（目前預設是上游，是保守配置。）

## 5. 沒有做的事

- **兩相 / 沸騰。** 130 °C 在足夠深度下仍是單相液態，但淺層或低壓場址不成立。
- **浮力對流。** 冷水較重會下沉，2D 水平模型看不到。真實系統的冷鋒面會沿
  底部推進得比本模型快。
- **上下蓋層的熱傳導。** 儲層會從上下岩層再取熱，讓熱突破**更晚** ——
  所以這方面本模型是保守的。
- **非均質 / 裂隙。** 這是本模型**最大的樂觀來源**。真實裂隙儲層的冷水會沿
  高滲透帶提早穿透，實測熱突破常常遠早於均質模型的預測。
- **井壁尺度。** 井被抹平成一格（20 m），生產溫度是格平均而非井壁溫度。

**一句話總結風險方向：** 蓋層傳導讓真實壽命更長，非均質讓它更短，而後者的
影響通常大得多。所以本模型算出來的年數應該當作**上限**看待，不是保證。
